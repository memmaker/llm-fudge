Glossary
- World: The deterministic instance of a game session, identified by a seed and containing all characters, state, and the turn/phase data.
- Entity: Anything named in the flat world state — a Character, Item, Location, or a freestanding narrative construct (a rumor, a faction's standing) with no engine-owned fields at all. Every entity has a unique, immutable ID and a `type`. The DM proposes the ID as a semantic handle (`merchant-alric`, never an opaque one); the engine validates rather than mints it. IDs are never reused, never reassigned, and never change, including when the entity moves or changes hands. Naming an existing ID is always an update, never a rename — the engine does not infer renames.
- Kernel: The small set of invariants the engine validates on every entity regardless of type — a unique ID, a `type`, and every reference (an item's `location`, an inventory's contents) resolving to an ID that exists, checked across one global keyspace shared by engine and narrative-only entities alike. The engine does not validate what an entity's narrative properties may contain; that is the DM's domain.
- Phase: The current lifecycle stage within a turn (e.g., setup, action, resolution).
- Turn: A single cycle of game activity, incremented as the narrative progresses.
- Character: An actor in the world (player, NPC, monster). Contains stats, health, and inventory. An Entity whose engine-owned fields the rules library computes and renders.
- NPC: Non-player character; a character controlled by the GM (LLM).
- Monster: A character representing a foe in combat or conflict.
- Item: An object that can be equipped or used by a character. Identified by a stable ID that survives every move — the name and place it is currently found by are a lookup, not its identity. Every item is in exactly one place — a Character's inventory or a Location — and moves between them rather than being destroyed and re-created (see Conservation).
- Location: A place the world holds (room, street, clearing), identified by a slug and optionally nested inside a parent. Holds the items lying in it. Nesting is organisational only and grants no reach between places.
- Scene: The Location the story is currently in, which is wherever the player character stands. Follows from the player character's own location, and changes when the State block says it does; a turn that does not say leaves the scene where it was.
- Spot: The short prose on an item lying at a Location saying where in that place it rests ("quivering in the door frame"). Part of the item's identity there: two stacks merge only when name and spot both match.
- Conservation: The rule that changing hands never creates or destroys. An item declared at a new location is relocated, carrying its ratings and wording with it; only something genuinely entering the world is created, and only `count: 0` ends a thing.
- State block: The declarative world diff the DM writes after its prose, in the same syntax it reads the world state in. It states what is now true, not what to do about it: the engine derives which operation each change corresponds to and runs the rules that operation always ran. It is the sole channel for every change except health.
- Event tag: A mechanical transition the DM marks inline in its narration, rather than declaring as a resulting state. Reserved for changes whose end state under-determines the rules outcome, which today means health alone (`damage`, `heal`). The DM says what happened; the engine decides what state follows.
- Under-determination test: The rule dividing the State block from Event tags. Not "does changing this require game rules?" — nearly everything does — but "does the declared end state under-determine the rules outcome?" Position, ownership, quantity and creation fail the test and are declared; health passes it, because what a wound does depends on the wounds already there.
- Derived field: A field the world state renders as a convenience but does not store as its own fact — an inventory (which follows from where each item is), who is present in a place (which follows from where each character is), a wound penalty. Derived fields cannot be written. The State block holds authoritative facts and never cached views.
- Engine-owned concept: A fact the rules library computes and is the sole authority for — identity, existence, position, containment, ownership, inventory, equipment, health, combat, time, movement. The DM declares the resulting state and the rules library still performs every computation reaching it; health alone is stated as an event instead, and is not writable as state at all.
- Narrative properties: The facts only the DM's prose knows — mood, suspicion, a rumor's content, a relationship, an object's condition where no rule cares about it. Live in an entity's `narrative` map, which is the one open namespace: everything else the DM may write is a known field of that entity's type, and an invented field name is refused rather than silently kept.
- Retirement: What becomes of a thing that stops existing in the fiction. It leaves the active world state but keeps its ID, which is never reused, so every historical reference to it still resolves. Nothing important is erased: the world state holds what currently exists, the archive holds what existed.
- Event: One recorded change against a turn in the archive — which operation ran, the entity IDs it named, and a one-line headline of what happened, whether the change arrived as a tool call, an event tag, or a line of the State block. What an entity did across a session is queryable by unioning the events that name it, rather than searching the words of the narration.
- Die/Roll: A dice-based randomization mechanism used by rules (e.g., 4d6).
- RNG: Random Number Generator; seeded to produce deterministic results per World seed.
- LLM: Large Language Model that acts as the DM/Narrator.
- DM: Dungeon Master; the entity guiding narrative, here implemented by the LLM via structured rules tools.
- Rules library: The Go package that maintains deterministic state and enforces rule transitions.
- Rule: A constraint or operation from the fudge-based mechanics; implemented as library calls.
- Action: A unit of work the rules library can perform; e.g., a skill check.
- Serialization: JSON-based representation used for debugging, persistence, or inter-process communication.
- Query tool: A call the DM makes because it needs an answer it cannot supply itself — how the dice fell, what a table gave, what happened six turns ago, which of two options the player picked. Information runs engine to DM, so these must come before the prose, and they remain tool calls: a declarative block has no way to hand a result back. Distinct from the bookkeeping calls, which only ever wrote something down and are now the State block.
- Tooling: The internal API surface that exposes rules capabilities to the LLM without relying on shell commands.
